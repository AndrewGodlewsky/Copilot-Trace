How action categories work

Read / search, edit and execute use complete supported tool argument contracts. A tool invocation is a request, not proof of execution. Unrecognized or ambiguous records remain unknown. Delegation uses a subagent-start record, without borrowing later child metadata. An unsplit assistant message without tool requests is a response; split or phased messages remain unknown. Valid tool-request messages are ignored to avoid counting a proposal again as an invocation. Hook, permission, turn and result boundaries are ignored.

Live order uses Trace’s receipt order after history is ready; timestamps and chronology do not establish causality. Disconnects, missing receipts or retention changes leave the exercise unanswered. Retained practice uses recorded event order and hides the later window until each choice or skip.

Actor labels and sources

Labels describe recorded event roles, not who chose the next action.

User
Input in the user role. This can include host-supplied input, not only text typed by a person.
Assistant
Assistant output and model-turn markers. Reported reasoning is not a complete account of decisions.
Tool
Runtime tool execution, whether for the main chat or a subagent.
Hook system
Hook pipeline boundaries at lifecycle points. A record does not establish that a configured handler ran.
Permission system
Permission requests and recorded decisions. The label does not identify who approved.
Instruction loading
A skill was invoked or loaded. Its recorded trigger appears in the step.
Host
Session notices, interruptions and delegated-work lifecycle events.

    About this view

    A model turn is one iteration of the agent loop, not an entire user request. Its heading and closing marker share a recorded turn ID. Indented events were recorded between those markers for the same agent; this shows timing, not why an action happened. Tool cards can span turns; their individual boundary events show their own turn context.

    Tool boundaries share a card only with the exact same usable source-agent and call IDs. Missing boundaries remain partial: a missing completion does not mean a tool is still running. Conflicting boundaries keep their evidence but have no combined outcome. Elapsed time requires one start, one result and valid timestamps in that order; it measures the recorded interval, not model thinking or billable time.

    Observed action stages link structured assistant requests, invocation entries, permission records and tool results when their exact identifiers agree. They retain recorded order, which can put invocation entry before permission. Entry and approval do not prove an operation executed; a result reports the tool's outcome. Missing permission is unknown, never assumed approval. Ambiguous records stay separate, and a decision kind alone does not identify a person.

    Request chapters begin at main-chat idle input or a turn start linked to earlier queued input by its exact interaction ID. They show timing, not which input caused an action. Input can be host-supplied. Steering never starts a new chapter; missing delivery or linkage leaves boundaries unknown. Original events stay in order, and Chronological events removes the chapter headers. A new chapter or an interruption does not establish success or completion.

    Agent lanes use exact recorded source IDs, never display names. Unknown-source records remain unassigned. Positive reliable start/end timestamps support observed overlap, not simultaneous CPU work; equal or unreliable boundaries remain unknown. Main-chat bars cover paired model turns, not whole requests. Subagent completion, failure and cancellation are distinct; missing completion never means still running. Explicit spawning-tool IDs enable parent evidence links only when one retained invocation matches. Missing, conflicting or shortened evidence leaves the relationship unavailable.

    Recorded evidence only, with up to 300 recent supported events and 12,000 UTF-16 code units of raw evidence per record. Some host activity and earlier streaming updates may be unavailable. Trace keeps its copy of chat content in memory and makes no model calls.

    Filters only hide retained event rows. Tools includes recorded tool starts and results, not proof of file changes. Skills and hooks includes skill invocations and hook starts/results. Problems includes session errors or warnings, interruptions, failed subagents, and tool or hook results with an explicit failure. Other text, missing results and permission waiting do not establish a problem. Call and chapter headers retain their full context; Statistics always counts all retained events. Evidence-navigation buttons reset the filter to Everything and open the original event.

                            • 
          
                          • Constraints: What must hold? Example: “Keep the public API and avoid new dependencies.”
                            • 
          
                          • Allowed actions: What may the agent do? Example: “Edit the upload code and tests; ask before deployment.”
                            • 
          
                          • Evidence of success: How can the result be checked? Example: “Run the upload tests and report remaining failures.”
