# Footer implementation plan

Goal: add the requested utility footer and safe plugin diagnostics to Trace 0.1.5.

Architecture: plain HTML/CSS/ES modules, protected loopback endpoints, no added dependencies. See [design](../specs/2026-11-19-footer-design.md).

- [ ] Add shared bounded diagnostic journal and instrument observer lifecycle; test privacy and retention. Serve protected diagnostics and packaged release metadata; test boundaries.
- [ ] Add footer panels and text-size controls, serialized refresh/polling, clipboard/export fallbacks and issue link. Test polling races and retain current flow behavior.
- [ ] Update release instructions, checks, README and all version metadata. Run unit/check/runtime/package, obtain independent review and install validated preview through CLI.
- [ ] Record actual owner UI acceptance before verification/publication. Report pending checks explicitly.

Review focus: log privacy; duplicate polling after repeated refresh; errors when clipboard or downloads are blocked; large text in narrow panes; focus/expansion while events arrive. Keep diagnostics in memory and do not automate UI.
