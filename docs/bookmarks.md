# Surprising events

Expand an original event and use **Mark as surprising** below its recorded evidence. The button exposes its pressed state and toggles the mark; it does not edit the record, send a request or affect agent execution. The footer's **Surprises** dialog lists marks in marking order, with **Open original**, **Unmark** and **Clear all marks** controls. Closing the list keeps marks. Closing the Trace panel discards them.

This first version supports live records only, across every timeline view and activity filter. Prediction, retained practice, playback and synthetic demonstrations disable event marking and explain how to return to live. Live marks survive these modes, but their labels, list and count stay hidden so they cannot reveal a later prediction or playback event. Live retention checks continue in the background. Learning events never share the live mark collection, even when their IDs are identical.

There are at most 20 marks, including unavailable placeholders. Marking the same exact original is idempotent; activating an already pressed event toggle deliberately unmarks it. At the limit, a new mark is rejected with an explanation. Existing marks are never silently replaced or automatically dropped. Remove a mark or clear the list to make room.

Marks are references to currently retained originals, not an archive. For exact comparison, each active mark temporarily holds one immutable event projection, bounded to 65,536 serialized UTF-16 code units. At most 20 such comparison copies exist; oversized projections cannot be marked. This preserves every projected field for comparison, including exact source, raw evidence, Unicode, clipping and observation metadata. It does not use a lossy fingerprint. The panel still retains only the observer's bounded evidence: marking cannot recover an earlier omitted record, protected content or clipped raw data.

When an original changes, becomes ambiguous or leaves the live retained window, its comparison copy and visible label are discarded. The mark becomes an ordinal-only **Original unavailable** placeholder. It cannot navigate and never reactivates when that ID returns. A replacement event starts unmarked and can be marked deliberately as a new item; the old placeholder remains until removed. This makes retention loss visible without storing expired chat text or silently claiming a complete archive.

An original link checks the current list opening, live mode, mark membership and the complete unique current event projection. It then uses the existing original-evidence route: close the dialog, pause Follow, select chronological order and Everything, expand the raw evidence, and focus its event summary. Missing targets leave reading position unchanged. Marking, unmarking and clearing do not resume Follow or navigate the timeline. List rows stay in place through live arrivals; removing a focused row moves focus to an adjacent Unmark control, or Clear all marks when none remains. Escape returns focus to Surprises.

The list is cleared on mode transitions and rebuilt on each explicit opening. Delayed native close events cannot clear a newly opened list, and callbacks from a prior opening cannot act in it. Page teardown clears marks, comparison copies and list state; later callbacks are inert. The feature uses no storage, transcript export, diagnostics payload or model operation. Annotations, durable notes, cross-session search and a notebook remain outside this feature.

Disposable helper and connected DOM fixtures cover duplicate marking, the limit, literal Unicode, immutable comparisons, missing/duplicate/replaced/evicted originals, nested filtered navigation, live arrivals, clear/unmark focus, queued close/reopen, same-ID demonstrations, hidden prediction/playback prefixes, background live eviction and page teardown. Privacy checks exercise the real diagnostics collector and check that mark actions make no storage writes or requests. These fixtures do not prove native layout or accessibility.

Owner-performed checks remain pending under the authorized overnight UI deferral: unobtrusive placement; discoverability; narrow and short panes; 150% text; keyboard and screen-reader state, Escape and focus return; stable reading during live updates; clarity of unavailable placeholders and the limit; and original navigation from nested/filtered events. No browser or desktop UI automation was performed.
