# Retained activity playback

Open **Replay retained activity · Optional playback**, then **Start playback**. Trace copies the current retained window into memory and starts paused at its first event. **Previous** and **Next** move through that fixed sequence; **Play** advances one event every two seconds and becomes **Pause** while running. At the end it stops. An empty window offers Return to live, and a single-event window is already at its end.

This is playback of recorded evidence. It never sends a command, re-runs a tool, pauses the host agent or simulates the original execution speed. The optional prediction exercise is separate: return to live before switching modes. Playback controls cannot advance a prediction exercise.

The snapshot contains at most 300 events, using Trace's existing bounded evidence. It preserves recorded order, timestamp ties, source identities, original evidence, omissions and history status at capture. The defensive cap keeps the first 300 entries if an oversized snapshot is supplied. It cannot recover events outside that window or fill gaps, and chronology does not establish causality. Missing or duplicate event identities make playback unavailable; Return to live remains available.

All timeline views, Statistics, navigation, comparisons, glossary examples and original-evidence links use only the prefix through the current step. Later results cannot annotate earlier steps until reached. Going backward closes inspectors that could retain later evidence. Current capability and instruction catalogs are suspended. Links continue to target the frozen source even if live retention evicts it or a same-ID live record changes.

Live capture continues independently. The activity indicator counts newly accepted supported live callbacks since entering playback or prediction practice, using Trace's receipt counter rather than retained length. It includes arrivals that are subsequently evicted, but excludes hydrated history, buffered callbacks before history was ready, duplicate records and streamed deltas. It reveals no categories or event text. The count stays unknown if history was not ready at capture or its observed receipt boundary becomes invalid; it is not an execution-progress measure.

**Return to live view** selects the latest received live snapshot and discards playback state. Its **Follow live when returning** checkbox starts unchecked every time. Leaving it unchecked keeps following paused; selecting it explicitly resumes following. A disconnected feed remains labeled as disconnected. Exit, page close and preference changes invalidate pending timer callbacks; late callbacks cannot move a replacement snapshot.

Controls are native buttons and a checkbox for Tab, Enter and Space operation, with visible focus. Boundary buttons stay focusable but announce their disabled state and do nothing. Playback never auto-starts. Reduced-motion preference disables automatic playback while keeping manual steps available; enabling it while playing stops the timer, and disabling it does not restart playback. Opening an event, nested evidence/analysis disclosure or footer inspector, linking a validation result, changing the view/filter, or collapsing playback pauses it. Live arrivals do not move the cursor, focus or reading position.

Helper and DOM-fixture tests cover prefix order and bounds, empty/single/end states, partial history, frozen originals, reverse stepping, live eviction, mode isolation, focus handling, reduced-motion changes and timer cancellation races. They do not establish native layout or keyboard behavior. Owner checks remain pending for narrow/short panes, enlarged text, keyboard/focus, motion preferences, comprehension and reading position during real live activity under the authorized UI deferral. Nothing is persisted or imported.
