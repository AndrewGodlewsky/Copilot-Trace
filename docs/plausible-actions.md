# Plausible next actions

The viewer’s **Plausible next actions · Optional learning** disclosure offers locally authored alternatives for selected recorded observations. Each card separates its recorded observation and limits from two possible actions with explicit conditions. The alternatives are educational: they are not a forecast, required sequence, exhaustive action set, probability estimate or account of an agent’s hidden plan.

Opening the disclosure selects up to three latest supported observations from at most 300 events in the displayed window. The scope text reports other supported observations not shown and omitted history. Cards remain separate even when activity overlaps; Trace does not combine them into one plan or decide which action should come next. An older observation’s relevance to the current request is unknown.

| Supported observation | Required evidence | What remains unknown |
| --- | --- | --- |
| Recorded failure | One complete matched invocation/result pair with `success: false`, or a supported process result with a typed nonzero exit. Protocol status and process exit are stated separately. | Cause, recovery, need for another attempt and overall task outcome. Later success does not erase an earlier failure. |
| Successful retrieval report | A paired success with returned text under an existing supported read contract in `toolOutcomes`, such as `view` or `web_fetch`. | Relevance, usefulness, sufficiency and task correctness. Tool names or output prose alone cannot establish retrieval. |
| Permission evidence gap | A complete, unambiguous retained request recognized by `observedActivity`, without a matching decision for its exact source and request ID. Unsupported recovery ownership is excluded. | Current waiting, approval and execution. A missing decision can reflect old or incomplete history. |
| Completed check process | A recognized literal `validationChecks` command and matched successful protocol result with a valid typed zero process exit, also accepted by `toolOutcomes`. Nonzero exits use the failure scenario. | Assertion counts, suite coverage and whole-task correctness. Output text and assistant statements are not authoritative validation. |

Tool pairs require exact source/call identity, usable unique event IDs, complete unshortened raw evidence, consistent projected status and compatible recorded provider fields. Duplicate, contradictory, clipped or protected-content-omitted boundaries cannot support a scenario. Unsupported contracts and missing evidence produce general guidance rather than a personalized prediction. The implementation reuses existing presentation helpers; it adds no loose prose classifier or adjacent-event inference.

The disclosure starts closed and pauses Follow live and automatic playback when opened. It freezes the selected content until closed and reopened. Unrelated arrivals do not replace cards or change their order. A changed, ambiguous, settled or evicted observation permanently disables that selection’s evidence and glossary controls; its old lesson stays visibly labeled as selected material. Earlier failures stay inspectable when newer operations arrive, including when they fall outside the latest-three selection rule. Closing clears the selection. Mode changes, reverse playback and page closure release it and invalidate detached controls.

Evidence buttons use the existing guarded original-event navigation and preserve literal Unicode. Glossary buttons use the existing glossary inspector with the selected event. Live prediction, retained practice, playback and synthetic examples supply only their currently displayed prefix; unseen outcomes and annotations are never inputs to this feature. Synthetic observations are explicitly labeled. No authored suggestion enters recorded events, Statistics counts or diagnostics.

The feature never executes an option, edits the composer, contacts a model or persists selections. It uses existing served presentation assets and changes no host integration.

Helper and DOM fixtures cover all four states, no evidence, malformed and clipped identities, provider conflicts, overlapping sources, future-prefix exclusion, quiet arrivals, exact stale links and close behavior. They do not prove rendered geometry, native keyboard behavior or educational clarity. Owner acceptance remains pending for collapsed/expanded usability, narrow and short panes, enlarged text, keyboard/focus, live reading, source/glossary return and all source-mode labels under the authorized UI deferral for this iteration.
