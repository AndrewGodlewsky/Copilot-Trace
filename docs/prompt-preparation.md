# Prompt preparation

Open **Prompt prep** in the footer to consult five optional questions: desired outcome, relevant files or examples, constraints, allowed actions, and evidence of success. Each has an authored developer example. The checklist works without filling in a form. More detail may clarify a request; it does not guarantee the agent's action sequence or correctness.

The single optional draft starts empty. **Copy outline** copies five blank headings when the draft has zero characters. Otherwise **Copy draft** copies the exact text, including whitespace-only input, Unicode, markup and multiline text. Examples are never inserted into the draft. Nothing is read from the current chat, a replay, a prediction exercise or a synthetic lesson. Preparing a prompt does not send a message, change the host composer, run a model, score the draft or authorize host actions.

Copying is an explicit action. The copy limit is 16,000 UTF-16 code units, as disclosed beside the editor; some emoji use two units. The limit applies to the whole copy. An oversized paste stays intact and editable: no `maxlength`, truncation or partial copy is applied. The copy button is disabled until the draft is within the limit. Users can shorten it or select text in the editor and use their normal copy shortcut. The editor retains oversized text only until it closes; generated copy/fallback text stays within the bound.

If clipboard access is absent or denied, a read-only text area shows the exact attempted copy, selects it and explains how to copy manually. Error text is fixed and contains no raw exception. Draft text is never sent to diagnostics or to a server, and is never persisted by Trace. A requested clipboard write may still finish after closing the dialog; Trace cannot retract it. Late success or failure cannot change the new draft, restore a discarded fallback or announce an outdated result.

**Close and discard**, Escape, closing the dialog to switch footer panels, and leaving the page clear the draft, fallback and status. Reopening starts empty. The existing modal panel lifecycle restores focus to the opener, pauses Follow and playback on inspection, and continues collecting live evidence independently. The prompt panel has no evidence banner because the user's draft is not a synthetic event.

Automated helper and DOM fixtures cover exact empty, partial, full, whitespace, Unicode and multiline drafts; the copy bound; clipboard success, denial and missing APIs; queued close events; edits and repeated opens while copies are pending; Escape, footer transitions and pagehide; and draft-free diagnostic output. They do not establish native layout, browser clipboard behavior, textarea platform line-ending behavior, focus trapping or screen-reader announcements. Owner acceptance of usefulness, narrow/short panes, 150% text, keyboard/focus, clipboard permissions and discard clarity remains pending under the authorized UI deferral for issue 38.
