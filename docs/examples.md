# Synthetic example library

Open **Example library**, load the packaged lessons, choose a demonstration, and use the existing playback **Previous / Next** controls. Optional Play advances one event every two seconds; reduced motion keeps navigation manual. Nothing in a lesson is executed. The library needs only Trace’s local protected asset server, with no external download, model request, imported transcript or saved user data.

Every run is locally authored for Trace. Messages, relative `demo/` paths, source identifiers, times and outcomes are invented. The active viewer and Statistics, glossary and argument inspectors label that scope as **Synthetic demonstration**. The ordinary viewer describes the supplied synthetic event facts; lesson notes are labeled **Authored annotation**, and other possible actions are labeled **Hypothetical alternative — not an event**. These examples are not recordings of real agents or claims about hidden reasoning.

| Demonstration | Intended lesson | Evidence limits |
| --- | --- | --- |
| Explore a small repository | Separate requested reads, returned text and an assistant summary. | Two returned files do not establish relevance or complete repository coverage. |
| Follow a bug-fix workflow | Compare a failing process result, a requested edit and a later check. | Invocation entry can precede a permission decision. The example omits the permission request and decision source, so attribution stays unknown. Protocol success differs from process exit; exit zero does not establish complete correctness or causality. |
| Recover after a failed operation | Inspect a failure, then compare a later operation with changed arguments. | A later zero exit does not prove an automatic retry, the cause of recovery or correctness of the reported output. |

Only events through the current step enter the viewer, original-evidence links, Statistics and adjacent inspectors. An annotation appears only after its referenced event is revealed. Moving backward removes later notes and closes inspectors. Full lesson metadata states the learning objective without exposing later event bodies. Prediction practice and live playback cannot start while a demonstration is active; return to live first.

Live capture and its bounded retained window continue independently. Example events never enter the observer, live receipt cursor, live counts or prediction outcomes. A separate status reports only the number of new supported live receipts. Demonstration snapshots have no observation receipts. Each mode has separate viewer caches and claim/result links, including when event IDs happen to match.

Returning restores the live view, activity filter, navigation category and surviving event disclosures and user links, then reconciles the latest retained live data. Links can expire if their exact evidence changed or was evicted. Footer inspectors close when switching modes. With **Follow live when returning** unchecked, Trace restores the saved page scroll offset, subject to the current document height; focus returns to **Open demonstration**. Checking Follow opts into following the latest live activity. This preserves a scroll offset, not an immutable visual anchor after live retention or layout changes.

## Supported packaged data

`web/examples.json` is a UTF-8 JSON document with `schemaVersion: 1` and `examples`. The package check requires the three lesson IDs `exploration`, `bug-fix` and `recovery`. The shared browser/server validator accepts one to three examples, at most 30 events and 30 annotations per example, and at most 256 KiB for the entire UTF-8 document. The server reads at most that limit plus one byte before rejecting oversized data. Identifiers have a 128-character bound and an explicit `synthetic:<lesson-id>:` namespace. Text fields have individual bounds; event JSON must fit Trace’s 12,000 UTF-16-unit evidence bound. Strings are displayed literally and are not interpreted as HTML, links or commands.

Each example supplies an ID, `kind: synthetic`, title, intended lesson, provenance, events and annotations. Each annotation references one unique event and has separate `note` and `alternative` text. The version-one event subset is deliberately small: idle user messages, unsplit assistant messages, tool starts/results, and approval decisions with unknown attribution. Tool starts support only the selected `view`, `edit` and `powershell` argument shapes. Results may include one typed `shell_exit`. Unknown properties, duplicate identities, malformed fields, out-of-order timestamps, orphaned or duplicate tool boundaries, inconsistent source/call pairs, and unsupported types are rejected. This is not an arbitrary event import format.

Lesson data is validated before serving and again before display. Missing, malformed or oversized JSON receives a protected HTTP 503, and the panel reports that examples are unavailable while live capture continues. Retry reloads the current server’s asset response; correcting an installation’s packaged files requires a new panel/server instance. Core JavaScript modules remain required application assets. The library is cached only in the open panel; active playback, timer and demonstration state are released on exit, and page close cancels an outstanding library request and releases the cache.

## Verification and remaining acceptance

Unit fixtures check all three lessons against the existing live projector, field and byte limits, source/call identities, literal Unicode, annotation separation, typed process exits and incomplete permission evidence. Server fixtures use disposable copies to test packaged routes and missing/malformed data without touching an installed plugin. DOM fixtures cover repeated live/example/practice transitions, hidden future evidence, same-ID claim isolation, live arrivals, state restoration, loading failures and stale callbacks. The installed-runtime fixture fetches the actual packaged assets and confirms that doing so creates no synthetic observer records or additional model requests.

These checks do not establish native layout, educational clarity or screen-reader behavior.
